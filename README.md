## 🧩 Page Object Model

This project uses the **Page Object Model (POM)** pattern.

Each web page is represented by a dedicated class.

For example:

```text
LoginPage
    ↓
LoginTests

ProductsPage
    ↓
ProductTests 

CartPage
    ↓
CartTests 

CheckoutPage
    ↓
CheckoutTests
```

This approach helps to:

* Separate test logic from UI locators
* Improve code readability
* Reduce code duplication
* Make locators easier to maintain
* Improve test reusability

## 🔍 Selenium Locators

The project uses different Selenium locator strategies depending on the element.

Examples:

```csharp
By.Id("user-name")
```

```csharp
By.ClassName("inventory_item")
```

```csharp
By.CssSelector(".inventory_item.price")
```

```csharp
By.XPath("//button[@id='login-button']")
```

### Important

`By.ClassName()` accepts only **one CSS class**.

Incorrect:

```csharp
By.ClassName("inventory_item price")
```

Correct:

```csharp
By.CssSelector(".inventory_item.price")
```

This is an important Selenium WebDriver rule when working with elements containing multiple CSS classes.

## 🏗️ Example Page Object

Example of a Page Object:

```csharp
using OpenQA.Selenium;

namespace SauceDemo.Pages;

public class LoginPage
{
    private readonly IWebDriver driver;

    private readonly By username =
        By.Id("user-name");

    private readonly By password =
        By.Id("password");

    private readonly By loginButton =
        By.Id("login-button");

    public LoginPage(IWebDriver driver)
    {
        this.driver = driver;
    }

    public void Login(string user, string pass)
    {
        driver.FindElement(username).SendKeys(user);
        driver.FindElement(password).SendKeys(pass);
        driver.FindElement(loginButton).Click();
    }
}
```
